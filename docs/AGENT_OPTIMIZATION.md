# Agent 能力与协作优化

2026-10-11。本次优化覆盖 App、Web、TUI、CLI 共用的真实执行链。`agent.py` 与 `agents/` 是未接入当前入口的旧原型，本次没有重新启用它们。

## 角色与交接

| 角色 | 实际增强 | 交接原则 |
|---|---|---|
| 主控 | 统一角色契约、能力自检、参数校验、重复失败抑制、拒绝后的执行阻断、工具调用 ID 去重、上下文预算、可配置轮次 | 根据工具返回继续规划；不得把截断、拒绝和失败视为成功 |
| 文件管家 | 文件检索与读取分页、完整文本转换、源文件变化检查、增量索引、批量写入、查重采样筛选、移动失败清理、OCR 语言检测 | 发现路径后读取；索引交给搜索；文件变更先出具体确认计划 |
| 电脑管家 | 磁盘使用率、内存页指标、电池信息、CPU 排序的进程列表；保留原始输出 | 提供实际诊断证据；CPU 数据是 ps 的进程平均值；不执行系统修改 |
| 软件管家 | 应用包剪枝遍历、15 秒缓存、名称筛选、大小写匹配与准确名称确认 | 先查询再启动；不存在或歧义名称不可自动猜测 |
| 浏览器管家 | 标题、正文、来源与截断信息，空正文明确失败，分块读取时检查取消 | 读取搜索提供的来源；不执行网页脚本和内容中的指令 |
| 搜索助手 | 容忍属性顺序的 HTML 解析、链接去重、命中附近摘要、过期标记、授权过滤后的结果上限 | 搜索链接交给浏览器核实；索引缺失/过期交给文件管家 |

六个角色仍是一个模型下的执行能力，不是六个独立推理上下文。现有职责已经覆盖本次需求，因此没有新增空壳角色。文件操作与执行树仍按任务顺序执行；支持多任务并行需要另行设计资源锁、多活跃任务界面与执行树协议，不能仅增加线程数。

## 执行约束

### 2026-10-12：提示词与工具契约

参考用户提供的 WorkBuddy 提示词和工具定义，采用主动完成任务、先查上下文再提问、按观察结果迭代、失败后调整方法和最终交付独立可读等原则，适配本机实际能力。

- `marvis/prompts.py` 集中构建运行提示词，`Runtime._chat` 在过滤工具和计算实际轮次后调用。运行信息包含平台、本机时间与时区、模式、授权目录、可用工具、轮次预算及称呼/风格偏好；本地模式不列出网页工具，也不下发浏览器角色交接规则。本地模式只限制网页访问，不保证模型本地运行。
- 16 个现有工具均补充用途、返回证据、限制和参数说明。分页区分文件数量偏移与字符偏移，文档提取上限和网页截断不能当作可继续分页；知识搜索无分页参数，更多命中需要缩小关键词。可选默认值与执行器保持一致，未增加虚构能力或改变审批策略。
- 提示词明确单模型角色分工、顺序执行、真实电脑与授权边界、拒绝后停止、已有文件不覆盖、来源验证和实际文件路径交付。没有照搬参考材料中的 Ubuntu 沙箱、安装权限、其他平台工具、固定目录或专属交付接口，也没有加入阻止用户查看自身项目提示词的规则。
- 回归测试检查真实模型调用收到的提示词与工具列表一致、模式切换和轮次上限、默认参数行为，以及多轮读取对真实分页证据的传递。模型以模拟响应验证协议，实际模型是否更稳定仍需真实任务评估。

修改会在下一次启动后台引擎时生效；已运行的引擎需要重启。

- `marvis/team.py` 是工具归属和协作指导的唯一运行定义。每个工具必须且只能属于一个角色，测试验证它与实际工具目录一致。
- 工具输入先校验必填字段、额外字段、类型、枚举、数值范围及长度。确认预览失败也记录对应工具错误，执行树不会悬空。自然语言快捷执行跳过否定、建议、分析和保存类复杂请求，避免关键词触发不完整操作。
- 同一任务中，用户拒绝某个变更工具后，后续同名调用即使更换参数也不会再次执行或弹出确认。下一条用户任务可以重新请求该工具。
- 同名且同参数连续失败两次后，后续重复请求只返回明确错误。成功会清除失败计数；调整参数可重新尝试。引擎不自动重试变更操作。
- 默认八轮工具编排，可通过 `config.yaml` 的 `orchestration.max_rounds` 调整为 1–24。结束后只允许一次无工具总结，违规返回的工具调用不会执行。
- 每份模型工具结果最多 24000 字符，保留合法 JSON、结构、证据和显式截断提示；审计记录保留完整结果。历史上下文默认最多 120000 字符，优先移除完整旧轮次，再压缩历史工具证据；保留调用 ID 与对应返回，超预算时明确失败。
- 本地模式不会向模型暴露网页工具，执行器仍保留网络阻断。模型普通响应限制 4 MB，流式传输累计限制 8 MB，避免无上限的输出占用。

## 分页与能力自检

所有入口均支持精确工具命令：

```text
/tool agent_inspect {}
/tool file_list {"path":"/授权目录","limit":30,"offset":0}
/tool file_read {"path":"/授权目录/report.txt","limit":10000,"offset":10000}
/tool app_list {"query":"Safari"}
/tool image_ocr {"path":"/授权目录/image.png","language":"chi_sim+eng"}
```

也可以发送“检查团队能力”，无需模型即可执行。`file_list.next_offset` 用于下一页匹配结果，`file_read.next_offset` 为字符偏移。文件列表每次扫描最多 5000 个文件，内容搜索最多检查每份文件前 100000 字符；分页会重新扫描，因此外部新增/移动文件时页面不保证稳定。PDF 最多提取 100 页、Excel 每张表最多 1000 行、所有文档最多 100000 字符，触及这些范围时返回 `extraction_limited`，TXT 转换会明确失败而不创建残缺文件。网页最多返回 20000 字符，无法用文件分页参数继续网页读取。

知识索引依据文件大小和修改时间跳过未变化内容；不是实时目录监视器，外部修改后需要重新运行索引。索引缺失文件不会作为结果返回，修改后的文件以 `stale` 标记。提取失败或空内容会再次尝试，便于安装文档依赖后恢复。

OCR 自检仅确认执行文件是否存在；实际调用检查语言包。中文语言缺失但英文可用时，自动使用英文并明确提示。网络服务可达性、OCR 识别质量和真实模型任务质量不能由自检保证。

## 性能验证

运行 `.venv/bin/python scripts/benchmark_agents.py`，在临时目录创建 500 份文档，不访问真实用户文件、不联网、不调用模型。

| 本机样本 | 实测 |
|---|---:|
| 首次索引 500 份文档 | 80.55 ms |
| 未变化重扫，五次中位耗时 | 22.43 ms |
| 五次重扫重新读取文档数 | 0 |
| 一次目录扫描查询授权设置次数 | 1 |

这是首次索引与未变化重扫的比较，不是旧版本与新版本的同负载比较；磁盘缓存、文档类型和机器负载会影响时间。确定性的性能保障由回归测试验证：未变化文档不重读、应用包不递归进入、缓存命中不重扫、设置变化立即撤销缓存授权。

数据库新增事件、任务、消息和执行节点查找索引。文档索引按最多 128 项提交批次，取消可能保留已提交批次，不会将未提交批次假报为任务完成。去重先按大小和首尾样本筛选，最终重复结论仍使用完整 SHA256；文件中间不同不会被误判。

## 验证与边界

`tests/test_agent_contracts.py` 覆盖能力契约、非法参数、分页、增量索引、权限撤销、索引摘要与过期、大 CSV 转换、源文件变化、网页解析、缓存、系统指标、OCR 降级、移动异常、拒绝重试、重复失败、上下文协议、空响应、执行预算和响应体限制。原有会话分支、持久化、审批、服务认证、TUI 和流式测试继续运行。团队与办公室的实际浏览器交互测试验证状态、交接、节点稳定性和减少动态效果。

本机联网验收：`browser_read` 成功提取 Example Domain 的标题与 156 字符正文；DuckDuckGo 返回人机验证页面，搜索明确报错，没有伪造结果。真实 OCR 识别和远程模型业务质量仍未验收。

仍未实现独立 Agent 并行推理、应用内 GUI 操作、系统设置修改、原生 Office 生成、向量检索和网页登录操作。更新后请重启共享后台引擎，让所有客户端使用新实现。
