# 文档知识库

知识库保留两条搜索路径：本机 SQLite 的关键词匹配，以及 OpenViking 文档资源的语义检索。原文件不会被索引操作修改。文档资源使用独立的 `viking://resources/marvis-knowledge-<工作空间标识>`，不与用户长期记忆混用。

## 使用

1. 在设置中授权资料目录，再在知识库页面输入目录并点击「建立 / 更新索引」。页面保留在知识库，显示扫描结果。
2. 空搜索框默认展示已索引、仍存在且已授权的文件。支持类型筛选，每页 24 份。
3. 「关键词」匹配文件名或已提取内容；「语义搜索」接受自然语言问题。空框在两种模式下都展示文件列表，不调用语义 API。
4. 点文件标题或「预览」直接读取原文件，最多展示 12000 字符；图片展示预览。「让 AI 阅读」与「OCR」进入对话并执行对应工具。
5. 「同步 / 重试」唤醒后台同步并立即重试失败项目。「服务设置」打开 OpenViking 所在的长期记忆设置。

## OpenViking 生命周期

复用现有 OpenViking 服务与客户端，当前服务入口由「启用长期记忆」开关控制。关闭此开关、离线运行、服务尚未启动，或本地模式下配置的是远程服务时，语义检索显示不可用；本机关键词搜索和浏览仍可用。托管服务使用随包携带的本地嵌入模型，文档语义处理使用已配置的生成模型。使用外部部署时，索引文本会发送至配置的 OpenViking 端点。

后台每 3 秒检查已索引文档，已有文档也会自动补充语义索引。每轮最多提交 8 份文本快照，使用临时上传 API，不依赖外部服务访问本机路径。任务 ID、文档指纹和 URI 保存在 SQLite 中，重启后继续跟踪。提交响应丢失时通过资源 URI 查询已接受任务，避免直接重复上传。只有 OpenViking 任务返回 `completed` 才显示「语义就绪」。失败项目每 60 秒自动重试，也可以手动重试。

原文件修改后显示「需要更新」，停止用旧文档做语义检索。重新建立索引后同步新文本。原文件删除或授权移除后，从浏览和搜索结果中即时排除，服务可用时后台清理对应资源；尚未完成的导入先等待结束，再删除，防止删除后重新出现。此机制检查已索引文件，不会实时扫描目录发现新增文件；新增文件需要再次建立索引，或配置已有的「更新文档索引」自动化。

## 范围与限制

- 本地扫描最多 5000 个文件；达到扫描上限会提示缩小目录。
- 文本、代码、PDF、DOCX、XLSX 沿用现有解析器与提取上限。语义搜索基于已提取的文本快照，不能保证覆盖超出提取上限的全文。
- 图片只索引文件名和元数据。OCR 仍为独立操作，不自动写回语义索引；扫描 PDF 也不自动 OCR。
- 语义检索最多召回 100 个候选，再按本机授权、存在性、文档指纹去重和过滤。结果保留原文件路径；服务不可用与无匹配结果有不同提示。
- 当前不提供语义索引独立于长期记忆服务的启停开关。

## API 与 Agent 工具

- `GET /api/knowledge?q=&mode=keyword&category=&offset=0`：浏览 / 搜索，返回 `files`、`total`、`has_more`、`sync` 与状态。
- `GET /api/knowledge-preview?path=...`：读取已索引且授权的文件文本。
- `POST /api/knowledge-sync {}`：唤醒同步并重试失败项目。
- `knowledge_search` 工具保留非空 `query`，新增可选 `mode: keyword | semantic`，默认为 `keyword`。语义结果 `status=unavailable` 不表示没有资料。
